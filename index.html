01Mental model

Git stores snapshots, not diffs. Every commit is a full picture of your project, identified by a hash, pointing back to its parent(s). Branches are just movable labels on commits.

Commit

An immutable snapshot plus metadata (author, message, parent hashes). Identified by a SHA like a1b2c3d.

Branch

A lightweight pointer to a commit. Committing moves the current branch forward automatically.

HEAD

“Where you are now.” Usually points to a branch; if it points straight at a commit, you’re in detached HEAD.

Remote

Another copy of the repo (e.g. on GitHub). origin/main is your local memory of where main is on origin.

02Setup & config

Config lives at three levels: --system, --global (your user), and --local (this repo). More specific wins.

Identity

Stamped on every commit you make.

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Sensible defaults

Modern settings worth turning on.

git config --global init.defaultBranch main
git config --global pull.rebase true
git config --global push.autoSetupRemote true
git config --global rerere.enabled true
git config --global core.editor "code --wait"

Aliases

Shortcuts for commands you type constantly.

git config --global alias.st "status -sb"
git config --global alias.lg "log --oneline --graph --all --decorate"
git config --global alias.undo "reset --soft HEAD~1"

Inspect config

See every value and which file set it.

git config --list --show-origin
git config --global --edit

SSH key for GitHub

Authenticate without passwords.

ssh-keygen -t ed25519 -C "you@example.com"
cat ~/.ssh/id_ed25519.pub   # paste into GitHub → Settings → SSH keys
ssh -T git@github.com

Sign commits

Show a “Verified” badge using your SSH key.

git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_ed25519.pub
git config --global commit.gpgsign true

03Starting a repo

Create a new repo

Turn the current directory into a Git repository.

git init
git init my-project       # create a new folder

Clone an existing repo

Download a full copy including history.

git clone https://github.com/user/repo.git
git clone git@github.com:user/repo.git my-dir
git clone --depth 1 <url>      # shallow: latest commit only
git clone --filter=blob:none <url>  # partial: fetch file contents lazily

04Staging & committing

The staging area lets you craft exactly what goes into each commit — even individual lines of a file.

See what changed

Status overview and line-level diffs.

git status -sb
git diff              # unstaged changes
git diff --staged     # what will be committed
git diff --word-diff  # inline word changes

Stage changes

Choose what goes in the next commit.

git add file.txt
git add .              # everything in this dir
git add -p             # pick hunks interactively
git add -u             # tracked files only

Commit

Record the staged snapshot.

git commit -m "Add login form"
git commit -am "Fix typo"   # stage tracked + commit
git commit --amend          # edit the last commit
git commit --amend --no-edit

Move & delete files

Let Git track renames and removals.

git mv old.js new.js
git rm file.txt
git rm --cached secrets.env  # untrack, keep on disk
Good commit messagesShort imperative summary (≤50 chars), blank line, then the why. “Fix race in session refresh” beats “fixed stuff”.

05Inspecting history

Browse the log

Many ways to slice history.

git log --oneline --graph --all
git log -p path/to/file      # patches for one file
git log --since="2 weeks ago" --author="Ana"
git log main..feature        # on feature, not main
git log --follow file.js     # across renames

Search history (pickaxe)

Find when a string was added or removed.

git log -S "apiKey"           # count of string changed
git log -G "fetch\(.*\)"      # regex in diff
git log --grep="hotfix"       # commit messages

Look at a commit

Inspect any object.

git show a1b2c3d
git show HEAD~2:src/app.js    # file at that commit
git show --stat HEAD

Who changed this line?

Line-by-line authorship.

git blame app.js
git blame -L 40,60 app.js
git blame -w -C app.js   # ignore whitespace, detect moves

Search the code

Fast grep over tracked files.

git grep "TODO"
git grep -n "useState" -- '*.tsx'
git grep "old_api" v1.0     # at a tag

Stats

Who contributes and how much.

git shortlog -sn
git diff --stat main...feature
git count-objects -vH

06Branching

Branches are cheap — a 41-byte file. Make one for every feature, fix or experiment.

A feature branch diverging from main.

Create & switch

switch is the modern, focused alternative to checkout.

git switch -c feature/login     # create + switch
git switch main
git switch -                    # previous branch
git switch -c fix origin/fix    # track a remote branch

List branches

Local, remote, merged or stale.

git branch -vv            # with upstream + last commit
git branch -a             # include remotes
git branch --merged main
git branch --sort=-committerdate

Rename & delete

Clean up when you’re done.

git branch -m old-name new-name
git branch -d feature      # safe: only if merged
git branch -D feature      # force
git push origin --delete feature

Detached HEAD

Look around an old commit without a branch.

git switch --detach v1.2.0
# made commits? keep them:
git switch -c rescue-branch

07Merging & rebasing

Two ways to integrate work. Merge preserves history exactly as it happened. Rebase replays your commits on top of another branch for a linear history.

Merge

Combine another branch into the current one.

git switch main
git merge feature
git merge --no-ff feature    # always create merge commit
git merge --squash feature   # one combined change
git merge --abort

Rebase

Move your branch to start from a newer base.

git switch feature
git rebase main
git rebase --continue   # after fixing conflicts
git rebase --abort
git rebase --onto main old-base feature

Resolve conflicts

Edit the <<<<<<< markers, then stage.

git status                     # see conflicted files
git checkout --ours file.txt   # keep our version
git checkout --theirs file.txt # keep their version
git add file.txt
git mergetool

Better conflict markers

Show the common ancestor too — far easier to reason about.

git config --global merge.conflictstyle zdiff3
git config --global rerere.enabled true  # remember resolutions
The golden rule of rebasingNever rebase commits that others have already pulled. Rebasing rewrites hashes; shared history should only move forward.

08Remotes & collaboration

Manage remotes

Named URLs for other copies of the repo.

git remote -v
git remote add origin git@github.com:me/repo.git
git remote add upstream git@github.com:org/repo.git
git remote set-url origin <new-url>
git remote prune origin

Fetch vs pull

fetch downloads; pull = fetch + merge (or rebase).

git fetch --all --prune
git pull                 # fetch + integrate
git pull --rebase
git pull --ff-only       # refuse if not fast-forward

Push

Publish your commits.

git push -u origin feature    # set upstream
git push
git push --force-with-lease   # safe force push
git push --tags

Keep a fork in sync

Pull upstream changes into your fork.

git fetch upstream
git switch main
git rebase upstream/main
git push --force-with-lease
Prefer --force-with-lease over --forceIt refuses to overwrite the remote if someone else pushed since your last fetch.

10Stashing

Shelve uncommitted work so you can switch context, then bring it back.

Save & restore

A stack of temporary snapshots.

git stash push -m "wip: navbar"
git stash -u               # include untracked files
git stash list
git stash pop              # apply + drop
git stash apply stash@{1}  # apply, keep in list

Advanced stash

Partial stashes and branching from one.

git stash push -p              # choose hunks
git stash push -- src/api.js   # specific paths
git stash show -p stash@{0}
git stash branch new-branch    # branch from stash
git stash drop / git stash clear

11Reflog: the safety net

Git records every move of HEAD for ~90 days. If you committed it, you can almost always get it back — even after a bad reset --hard or a deleted branch.

Find where you were

Every checkout, commit, reset, rebase.

git reflog
git reflog show feature
git log -g --oneline

Recover

Point a branch back at the lost commit.

git reset --hard HEAD@{2}           # go back 2 moves
git branch recovered a1b2c3d        # resurrect a branch
git switch main@{yesterday} --detach

Undo a bad rebase

ORIG_HEAD remembers where you started.

git reset --hard ORIG_HEAD

Find dangling objects

Last resort for things never on a branch.

git fsck --lost-found
git fsck --unreachable | grep commit

12Rewriting history

Interactive rebase turns a messy series of commits into a clean story before you share it.

$ git rebase -i HEAD~4

pick   a1b2c3d Add user model
# reword = change message · squash = meld into previous · fixup = meld, drop message
fixup  e4f5a6b oops, typo
reword 7c8d9e0 add API endpoint
edit   1f2a3b4 Big commit to split
drop   5c6d7e8 debug logging

Common recipes

Autosquash fixups

Mark a fix for an earlier commit; Git places it for you.

git commit --fixup=a1b2c3d
git rebase -i --autosquash main

Split a commit

Mark it edit in the rebase, then:

git reset HEAD~1
git add -p && git commit -m "Part 1"
git add -p && git commit -m "Part 2"
git rebase --continue

Run tests on every commit

Rebase stops at the first failure.

git rebase -i --exec "npm test" main

Purge a file from all history

Use git-filter-repo (the recommended replacement for filter-branch).

pip install git-filter-repo
git filter-repo --path secrets.env --invert-paths
git filter-repo --replace-text expressions.txt
Leaked a secret?Rewriting history isn’t enough — anyone may have cloned it. Rotate the credential first, then clean the history.

13Cherry-pick & patches

Cherry-pick

Copy specific commits onto the current branch.

git cherry-pick a1b2c3d
git cherry-pick a1b2c3d..f6e5d4c   # range
git cherry-pick -x a1b2c3d         # note origin in message
git cherry-pick --no-commit a1b2c3d

Patches by email / file

Share commits without a shared remote.

git format-patch -3            # last 3 commits → .patch files
git am *.patch                 # apply as commits
git diff > change.diff
git apply change.diff          # apply as unstaged changes

Compare two versions of a branch

See what changed between rebases of a PR.

git range-diff main feature@{1} feature

14Bisect

Binary-search your history to find the exact commit that introduced a bug. 1,000 commits → about 10 steps.

Manual

Git checks out the midpoint; you test and report.

git bisect start
git bisect bad              # current commit is broken
git bisect good v2.1.0      # this one worked
# ...test, then:
git bisect good   # or: git bisect bad
git bisect reset

Automated

Let a script decide — exit 0 = good, non-zero = bad.

git bisect start HEAD v2.1.0
git bisect run npm test
git bisect skip   # if a commit can't be tested
git bisect log

15Worktrees

Check out several branches at once in separate folders, sharing one repository. No more stashing to review a PR or ship a hotfix.

git worktree add ../hotfix main            # existing branch
git worktree add -b review ../review origin/pr-42
git worktree list
git worktree remove ../hotfix
git worktree prune

16Tags & releases

Create tags

Annotated tags store author, date and message — use them for releases.

git tag -a v1.0.0 -m "First stable release"
git tag v1.0.0-rc1                # lightweight
git tag -a v0.9.0 a1b2c3d         # tag an old commit
git push origin v1.0.0

Use tags

List, describe and package.

git tag -l "v1.*"
git describe --tags         # v1.0.0-14-ga1b2c3d
git tag -d v1.0.0 && git push origin :refs/tags/v1.0.0
git archive --format=zip v1.0.0 > release.zip

17Submodules, sparse checkout & LFS

Submodules

Embed another repo at a pinned commit.

git submodule add https://github.com/lib/x libs/x
git clone --recurse-submodules <url>
git submodule update --init --recursive
git submodule update --remote

Sparse checkout

Only materialize the folders you need in a huge monorepo.

git clone --filter=blob:none --sparse <url>
git sparse-checkout set apps/web packages/ui
git sparse-checkout add docs
git sparse-checkout disable

Large File Storage

Keep big binaries out of the object database.

git lfs install
git lfs track "*.psd"
git add .gitattributes
git lfs ls-files

Speed up big repos

Background maintenance and filesystem monitoring.

git maintenance start
git config core.fsmonitor true
git gc --aggressive

19Common problems

The error messages you’ll actually hit, what causes them, and how to fix them. Search for words from your error to jump straight to it.

Pushing & pulling

Push rejected: remote has new work

! [rejected] main -> main (fetch first)
Updates were rejected because the remote contains work that you do not have locally.

Why: someone pushed since your last pull. Integrate their commits first, then push again.

git pull --rebase
git push

No upstream branch

fatal: The current branch feature has no upstream branch.

Why: a new local branch doesn’t know which remote branch to push to yet.

git push -u origin HEAD
# never see it again:
git config --global push.autoSetupRemote true

Divergent branches on pull

hint: You have divergent branches and need to specify how to reconcile them.

Why: both you and the remote have new commits, and Git wants you to choose merge or rebase.

git pull --rebase        # linear history
git pull --no-rebase     # merge commit
git config --global pull.rebase true   # set a default

Refusing to merge unrelated histories

fatal: refusing to merge unrelated histories

Why: you ran git init locally and the GitHub repo was created with its own README/license commit. The two have no common ancestor.

git pull origin main --allow-unrelated-histories

src refspec does not match any

error: src refspec main does not match any

Why: there are no commits yet, or your branch is called master, not main.

git branch --show-current   # what is it called?
git commit -m "Initial commit"  # if nothing committed
git branch -M main
git push -u origin main

File too large for GitHub

remote: error: File big.zip is 142 MB; this exceeds GitHub's file size limit of 100.00 MB

Why: the file is in a commit, so deleting it in a new commit isn’t enough. Remove it from history.

# in the latest commit:
git rm --cached big.zip && git commit --amend --no-edit
# in older commits:
git filter-repo --path big.zip --invert-paths
# or move it to LFS:
git lfs migrate import --include="*.zip"

Authentication

Password authentication removed

remote: Support for password authentication was removed.
fatal: Authentication failed for 'https://github.com/…'

Why: GitHub no longer accepts account passwords over HTTPS. Use the GitHub CLI, a personal access token, or SSH.

gh auth login
gh auth setup-git      # use gh as credential helper

Permission denied (publickey)

git@github.com: Permission denied (publickey).
fatal: Could not read from remote repository.

Why: no SSH key is loaded, or the key isn’t added to your GitHub account.

ssh -T git@github.com            # test the connection
ssh-add -l                       # loaded keys
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
git remote -v                    # ssh or https URL?

Repository not found

remote: Repository not found.
fatal: repository 'https://github.com/…' not found

Why: a typo in the URL, or the repo is private and you’re signed in as an account without access.

git remote -v
gh auth status
git remote set-url origin git@github.com:owner/repo.git

Branches & commits

Committed to the wrong branch

You made commits on main that belong on a new feature branch, and haven’t pushed them.

git branch feature            # save commits on a new branch
git reset --hard origin/main  # put main back
git switch feature

Commit belongs on an existing branch instead?

git switch right-branch
git cherry-pick <sha>
git switch -  && git reset --hard HEAD~1

Local changes would be overwritten

error: Your local changes to the following files would be overwritten by checkout

Why: you have uncommitted edits to files the other branch changes. Put them somewhere safe first.

git stash -u && git switch other && git stash pop
# or bring the changes along / commit them:
git switch -c new-branch

“You are in detached HEAD state”

You are in 'detached HEAD' state. You can look around, make experimental changes…

Why: you checked out a commit or tag rather than a branch. It’s harmless, but new commits won’t belong to any branch.

git switch -c keep-my-work   # keep commits made here
git switch main              # or just go back

Deleted a branch by accident

git branch -D prints the hash it deleted (was a1b2c3d). If that’s scrolled away, reflog has it.

git reflog | grep feature
git branch feature a1b2c3d

Dropped or lost a stash

Stashes are commits, so they linger as dangling objects until garbage collection.

git fsck --no-reflog | awk '/dangling commit/ {print $3}' \
  | xargs git log --no-walk --oneline --grep=WIP
git stash apply <sha>

Wrong name or email on commits

Fix your config, then rewrite the affected (unpushed) commits.

git config user.email "right@example.com"
git commit --amend --reset-author --no-edit   # last commit
git rebase -r main --exec "git commit --amend --reset-author --no-edit"

Undo a pushed merge on main

Don’t reset shared history. Revert it, keeping parent 1 (main) as the mainline.

git log --merges --oneline -5
git revert -m 1 <merge-sha>
git push

Need to bypass a hook

A pre-commit or pre-push hook is blocking an urgent fix. Use sparingly.

git commit --no-verify -m "Hotfix"
git push --no-verify

Stuck states

Stuck mid-merge or mid-rebase

error: You have not concluded your merge (MERGE_HEAD exists).

Why: a merge, rebase or cherry-pick stopped on a conflict. git status says which one; finish it or abort.

git status
git merge --abort        # or --continue
git rebase --abort       # or --continue / --skip
git cherry-pick --abort

index.lock exists

fatal: Unable to create '.git/index.lock': File exists.

Why: another Git process (often your editor) is running, or one crashed and left the lock behind. Make sure nothing is running, then remove it.

ps aux | grep -i git
rm .git/index.lock

Not a git repository

fatal: not a git repository (or any of the parent directories): .git

Why: you’re in the wrong folder, or the repo hasn’t been initialised.

pwd
git rev-parse --show-toplevel   # where's the repo root?
git init                        # if it's meant to be new

Editor opened and you can’t get out

Git opened Vim for a commit or merge message. Type :wq and Enter to save, or :cq to abort. Then pick a friendlier editor:

git config --global core.editor "nano"
git config --global core.editor "code --wait"

Files & diffs

.gitignore isn’t ignoring a file

Why: .gitignore only affects untracked files. If it was committed before, Git keeps tracking it.

git rm --cached .env           # or -r for a folder
git commit -m "Stop tracking .env"
git check-ignore -v .env       # confirm the rule matches

Whole file shows as changed

Why: usually line endings (CRLF vs LF) differing between Windows and macOS/Linux.

echo "* text=auto" >> .gitattributes
git add --renormalize .
git commit -m "Normalize line endings"
git config --global core.autocrlf input   # mac/linux

Only file permissions changed

old mode 100644
new mode 100755

Why: the executable bit flipped, often from copying files or using a shared drive.

git config core.fileMode false
git diff --summary | grep mode

Renaming only the case of a file

On macOS and Windows the filesystem ignores case, so readme.md → README.md can go unnoticed. Use git mv:

git mv readme.md README.md
# older Git: rename via a temporary name
git mv readme.md tmp && git mv tmp README.md

Conflict in a lock file

Don’t hand-merge package-lock.json, yarn.lock and similar. Take one side and regenerate it.

git checkout --theirs package-lock.json
npm install
git add package-lock.json

Submodule folder is empty

Why: the repo was cloned without --recurse-submodules.

git submodule update --init --recursive
git config --global submodule.recurse true

20Debugging Git itself

When Git does something you don’t expect, make it show its work.

Trace what Git is doing

Environment variables that turn on detailed logging for a single command.

GIT_TRACE=1 git pull               # commands & aliases run
GIT_TRACE_PERFORMANCE=1 git status # where time goes
GIT_TRACE_SETUP=1 git status       # repo & worktree discovery

Network & auth problems

See the HTTP or SSH conversation with the server.

GIT_CURL_VERBOSE=1 GIT_TRACE_CURL=1 git fetch
GIT_SSH_COMMAND="ssh -v" git fetch
git config --get-all credential.helper

“Where does this setting come from?”

Find which config file sets a value, and what the result is.

git config --show-origin --get pull.rebase
git config --list --show-scope
git var -l | grep -i editor

Is it the alias, hook or Git?

Rule out customisations one by one.

git config --get-regexp '^alias\.'
ls .git/hooks | grep -v sample
git -c core.hooksPath=/dev/null commit   # run without hooks
git --version

Slow repository

Measure first, then tune.

git count-objects -vH
git maintenance run --task=gc
git config core.untrackedCache true
git config feature.manyFiles true

Check repo health

Verify integrity and bundle diagnostics for a bug report.

git fsck --full
git diagnose -o ~/Desktop   # zip of repo stats
git bugreport               # system info template
Read the hintsGit’s error output usually ends with a hint: telling you the exact command to run. git status is the best first step for almost any confusing state.

21.gitignore

Pattern syntax

One pattern per line.

# comments start with #
node_modules/      # a directory anywhere
*.log              # by extension
/build             # only at repo root
docs/**/*.pdf      # any depth
!important.log     # re-include
.env*

Debug & scope

Why is this file ignored?

git check-ignore -v path/to/file
git status --ignored
# personal, unshared ignores:
echo "scratch/" >> .git/info/exclude
git config --global core.excludesFile ~/.gitignore_global

23Workflows

GitHub Flow

Branch off main, open a pull request, review, merge, deploy. Simple and great for continuous delivery.

git switch -c feature/search
# ...commit work
git push -u origin feature/search
gh pr create --fill

Trunk-based

Everyone integrates into main at least daily via small, short-lived branches. Unfinished work hides behind feature flags.

Git Flow

Long-lived main + develop, with feature/, release/ and hotfix/ branches. Suits versioned, scheduled releases.

Conventional Commits

Machine-readable messages that drive changelogs and semver.

feat(auth): add OAuth login
fix(api): handle empty response
docs: update README
feat!: drop Node 16 support

24Daily cheat sheet

git switch main && git pull           # start fresh
git switch -c feature/thing            # new branch
git add -p                             # stage carefully
git commit -m "Describe the change"
git fetch && git rebase origin/main    # stay current
git push -u origin feature/thing       # share
git lg                                 # look around (alias)
git reflog                             # when in doubt
